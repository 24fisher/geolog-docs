    Электронные голосования¶

    Общие правила голосований¶

    VOTE-REQ-001. Электронное голосование как управляемая функция¶

    Система должна поддерживать электронные голосования. Возможность проведения электронных голосований должна включаться и отключаться уполномоченной ролью как единая настройка системы.

    При отключённых электронных голосованиях электронные процедуры голосования в системе не запускаются. Правление продолжает принимать решения по действующему внеэлектронному порядку. Принятое вне системы решение при необходимости регистрируется в системе с указанием основания. Обращения и инициативы продолжают существовать и могут быть обработаны по действующему внеэлектронному порядку.

    Этап: MVP

    VOTE-REQ-002. Типы голосований¶

    Должны различаться голосования правления и общеклубные голосования. Правила допуска к голосованию определяются типом голосования и действующими бизнес-правилами.

    Этап: MVP

    VOTE-REQ-003. Создание голосования¶

    При создании голосования фиксируются инициатор, формулировка вопроса, варианты ответа, круг голосующих, дата и время начала, дата и время окончания и правила определения результата.

    Этап: MVP

    VOTE-REQ-004. Неизменность начатого голосования¶

    После начала голосования нельзя незаметно изменять вопрос, варианты ответа, круг голосующих или правила определения результата. Если требуется исправление существенных параметров, исходное голосование прекращается с указанием причины и создаётся новое.

    Право голоса, тайна и видимость¶

    Этап: MVP

    VOTE-REQ-005. Право голоса¶

    Система определяет право конкретного участника голосовать на основании его статуса, ролей и типа голосования на момент голосования.

    Этап: MVP

    VOTE-REQ-006. Один голос¶

    Один участник, имеющий право голоса, может подать не более одного действующего голоса в рамках одного голосования, если правила конкретного типа голосования явно не предусматривают иного.

    Этап: MVP

    VOTE-REQ-007. Фиксация факта участия¶

    Система должна достоверно фиксировать факт участия пользователя в голосовании и исключать повторное голосование.

    Этап: MVP

    VOTE-REQ-008. Тайна выбора¶

    Если голосование объявлено тайным, интерфейсы системы и обычный административный доступ не должны раскрывать, какой вариант выбрал конкретный голосовавший. При этом система должна сохранять возможность доказать корректность подсчёта и отсутствие повторного голосования техническими средствами.

    Этап: MVP

    VOTE-REQ-009. Открытое голосование¶

    Для открытого голосования результат конкретного участника может отображаться в соответствии с правилами видимости данного голосования.

    Этап: MVP

    VOTE-REQ-010. Результаты до окончания¶

    Правило видимости промежуточных результатов задаётся при создании голосования. По умолчанию итоговые результаты публикуются после завершения голосования.

    Завершение, результат и история¶

    Этап: MVP

    VOTE-REQ-011. Завершение голосования¶

    По достижении времени окончания система прекращает приём голосов и фиксирует итоговый результат.

    Этап: MVP

    VOTE-REQ-012. Досрочное прекращение¶

    Уполномоченная роль может досрочно прекратить голосование только с обязательным указанием причины. Такое голосование сохраняется в истории и не удаляется.

    Этап: MVP

    VOTE-REQ-013. Результат как основание решения¶

    Результат голосования может являться основанием решения правления или общеклубного решения. Связь результата с созданным решением должна сохраняться.

    Этап: MVP

    VOTE-REQ-014. История голосований¶

    Завершённые и прекращённые голосования сохраняются в истории вместе с исходной формулировкой, параметрами, итогами и причиной прекращения, если она была.

    Этап: MVP

    VOTE-REQ-015. Уведомления¶

    Участники, имеющие право голоса, должны получать предусмотренные системой уведомления о начале голосования и, при необходимости, о приближении срока окончания. После завершения должен быть доступен итог в соответствии с уровнем видимости.

    Этап: MVP

    VOTE-REQ-016. Журналирование административных действий¶

    Создание, запуск, досрочное прекращение, изменение глобальной настройки электронных голосований и публикация результата должны фиксироваться в журнале действий.

    Общеклубное голосование¶

    Этап: MVP

    VOTE-REQ-017. Снимок состава голосующих¶

    При запуске общеклубного голосования фиксируется снимок членов клуба с правом голоса. Этот снимок используется для определения кворума данного голосования и не изменяется задним числом при последующем изменении состава клуба.

    Этап: MVP

    VOTE-REQ-018. Кворум общеклубного голосования¶

    Кворум общеклубного голосования составляет более половины членов клуба с правом голоса из снимка состава. Необходимое количество участников рассчитывается как минимальное целое число, превышающее половину снимка. При 103 имеющих право голоса кворум составляет 52 участника.

    Этап: MVP

    VOTE-REQ-019. Определение результата при наличии кворума¶

    Если кворум достигнут, предложение считается принятым, когда голосов «За» больше, чем голосов «Против», если для конкретного типа решения отдельным действующим правилом не установлен иной порядок. Голоса «Воздержался» учитываются в числе принявших участие для кворума, но не добавляются к голосам «За» или «Против».

    Этап: MVP

    VOTE-REQ-020. Отсутствие кворума¶

    Если кворум не достигнут, решение не считается принятым независимо от соотношения голосов среди проголосовавших.

    Этап: MVP

    VOTE-REQ-021. Повторное голосование после отсутствия кворума¶

    После первого общеклубного голосования, не состоявшегося из-за отсутствия кворума, повторная попытка проводится после задержки, определённой системной настройкой GeneralVoteRetryDelayDays; начальное значение — 7 календарных дней. Повторное голосование проводится по той же формулировке с новым снимком состава имеющих право голоса. Если кворум повторно не достигнут, процедура завершается без решения.

    Количество повторных попыток остаётся структурным правилом процедуры и не является настройкой: допускается одна повторная попытка.

    Голосование правления¶

    Этап: MVP

    VOTE-REQ-022. Снимок состава правления¶

    При запуске голосования правления фиксируется состав членов правления, имеющих право участвовать в конкретном голосовании.

    Этап: MVP

    VOTE-REQ-023. Варианты голоса правления¶

    В голосовании правления используются варианты «За», «Против» и «Воздержался».

    Этап: MVP

    VOTE-REQ-024. Самоотвод¶

    Самоотвод члена правления исключает его из состава, используемого для определения результата конкретного голосования. Факт самоотвода сохраняется.

    Этап: MVP

    VOTE-REQ-025. Принятие решения правлением¶

    Решение правления считается принятым, если голосов «За» больше половины состава членов правления, имеющих право участвовать в конкретном голосовании с учётом самоотводов.

    Этап: MVP

    VOTE-REQ-026. Персональные голоса правления¶

    Персональные голоса членов правления в голосовании правления сохраняются. При успешном голосовании результат является основанием для автоматического формирования решения правления.

    Этап: MVP

    VOTE-REQ-027. Создание и запуск голосования правления¶

    Любой действующий член правления может создать и запустить голосование правления по вопросу, относящемуся к компетенции правления, если электронные голосования включены. Председатель правления не имеет исключительного права на создание или запуск такого голосования.

    После запуска голосование становится доступно всем действующим членам правления, имеющим право участвовать в конкретном голосовании. Право участия и состав голосующих фиксируются по правилам VOTE-REQ-005 и VOTE-REQ-022.

    Донабор в правление¶

    Этап: MVP

    VOTE-REQ-028. Донабор на вакантные места¶

    Для заполнения одного или нескольких вакантных мест проводится отдельная общеклубная процедура донабора. Донабор не является переизбранием действующего правления и не прекращает полномочия его действующих членов. При открытии процедуры фиксируется количество заполняемых вакансий.

    Этап: MVP

    VOTE-REQ-029. Самовыдвижение в правление¶

    Действующий член клуба, соответствующий формальным требованиям к члену правления, вправе самостоятельно выдвинуть свою кандидатуру на открытую процедуру донабора. Самовыдвижение означает согласие кандидата на получение полномочий. Правление не вправе отклонить допустимого самовыдвиженца по содержательным мотивам до голосования; система проверяет только установленные формальные условия допуска.

    До начала голосования фиксируется окончательный список допущенных самовыдвиженцев. После начала голосования список кандидатов не изменяется.

    Этап: MVP

    VOTE-REQ-030. Донабор как подтверждение полномочий кандидатов¶

    Основной смысл донабора — подтверждение клубом наделения самовыдвиженцев полномочиями, а не обязательный конкурс кандидатов между собой. Каждый кандидат оценивается независимо вариантами «За», «Против» и «Воздержался». Один голосующий вправе выразить выбор отдельно по каждому кандидату в рамках одного бюллетеня.

    Этап: MVP

    VOTE-REQ-031. Тайна и кворум донабора¶

    Донабор проводится тайно по VOTE-REQ-008. Для всей процедуры используется единый снимок состава голосующих и общий кворум по VOTE-REQ-017 и VOTE-REQ-018. Если кворум не достигнут, ни один кандидат по этой попытке не получает полномочий независимо от персональных результатов.

    Этап: MVP

    VOTE-REQ-032. Подтверждение кандидата¶

    При достигнутом кворуме кандидат считается подтверждённым клубом, если по его кандидатуре голосов «За» больше, чем голосов «Против». Голоса «Воздержался» учитываются в участии для общего кворума, но не увеличивают персональные результаты «За» или «Против».

    Если число подтверждённых кандидатов не превышает число вакансий, каждый подтверждённый кандидат получает место. Незаполненные вакансии сохраняются.

    Этап: MVP

    VOTE-REQ-033. Подтверждённых кандидатов больше, чем вакансий¶

    Если число кандидатов, прошедших персональное подтверждение по VOTE-REQ-032, превышает число вакансий, места получают кандидаты с наибольшим числом голосов «За» в пределах доступного количества мест. Рейтинг применяется только между уже подтверждёнными кандидатами.

    Если равенство числа голосов «За» на границе последнего доступного места не позволяет однозначно определить получателя вакансии, по спорной вакансии проводится дополнительное тайное общеклубное голосование только между связанными равным результатом кандидатами. Уже однозначно распределённые места не пересматриваются.

    Этап: MVP

    VOTE-REQ-034. Наделение полномочиями по результату донабора¶

    Успешный результат донабора является непосредственным основанием для включения подтверждённого кандидата в состав правления. Система фиксирует дату начала его полномочий и связь с процедурой донабора. Полномочия остальных действующих членов правления не изменяются. История состава правления сохраняется по GOV-REQ-002.

    Этап: MVP
