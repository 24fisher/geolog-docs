    Массовый ввод финансовых операций¶

    Назначение¶

    Экран предназначен для бухгалтера и позволяет одной процедурой зарегистрировать пачку финансовых операций разных типов: членские взносы, денежные компенсации субботников и клубные расходы.

    Экран описывает пользовательское представление уже установленных финансовых правил и не вводит самостоятельных правил расчёта, проведения операций или полномочий.

    Доступ¶

    Экран доступен бухгалтеру.

    Предусловие¶

    Перед вводом операций бухгалтер выбирает сезон, к которому относятся регистрируемые операции.

    Основной рабочий экран¶

    Основной элемент интерфейса — единая редактируемая таблица пачки финансовых операций.

    Каждая строка представляет одну будущую финансовую операцию. Бухгалтер может добавлять, редактировать и удалять строки до сохранения пачки.

    Общие элементы строки¶

    Поле/элемент Когда используется Содержание Нормативная основа
    Тип операции всегда членский взнос, денежная компенсация субботников или клубный расход FIN-REQ-007; FIN-CASE-004
    Сумма всегда сумма операции FIN-REQ-006, FIN-REQ-007, FIN-REQ-028; FIN-CASE-004
    Дата всегда дата фактической операции FIN-REQ-006, FIN-REQ-007, FIN-REQ-028; FIN-CASE-004
    Комментарий всегда пояснение бухгалтера к операции FIN-REQ-007, FIN-REQ-028; FIN-CASE-004
    Состояние проверки строки после ввода данных валидна строка или содержит ошибку/проблему FIN-REQ-007; FIN-CASE-004

    Строка прихода¶

    Для членского взноса и денежной компенсации субботников показываются поля:

    • участник;
    • сумма;
    • способ оплаты;
    • дата;
    • комментарий;
    • подтверждающий документ, если способ оплаты — перевод.

    Для наличного платежа подтверждающий документ не обязателен. Для перевода отсутствие подтверждающего документа является ошибкой и не позволяет провести соответствующую строку.

    Для денежной компенсации система дополнительно проверяет, что сумма/объём компенсации не закрывает больше текущего незакрытого остатка сезонной нормы.

    Нормативная основа: FIN-REQ-001, FIN-REQ-002, FIN-REQ-006, FIN-REQ-007, FIN-REQ-008, FIN-REQ-009; FIN-CASE-004.

    Строка клубного расхода¶

    Для клубного расхода показываются поля:

    • категория расхода;
    • сумма;
    • дата;
    • подтверждающий документ;
    • комментарий;
    • решение-основание, когда оно требуется действующими финансовыми правилами.

    Отдельное обязательное поле контрагента в MVP не используется.

    Если требуемое решение-основание отсутствует, система не блокирует регистрацию фактически совершённого расхода. Строка должна явно показывать проблему отсутствующего основания и после сохранения операция подлежит последующему рассмотрению.

    Если указанное основание не соответствует фактической цели или категории расхода, строка/операция должна явно показывать зафиксированное несоответствие. Регистрация факта расхода не означает его одобрения.

    Нормативная основа: FIN-REQ-007, FIN-REQ-028; FIN-CASE-004.

    Документы¶

    Подтверждающий документ относится к конкретной строке, а не ко всей пачке.

    Для перевода документ обязателен. Для наличного прихода документ не обязателен. Для клубного расхода подтверждающий документ обязателен.

    Интерфейс должен позволять пользователю однозначно видеть, к какой строке относится загруженный документ.

    Проверка пачки перед сохранением¶

    До проведения операций система показывает сводку пачки:

    Показатель Содержание
    Количество строк общее количество строк пачки
    Итоговые суммы суммы по введённым операциям в предусмотренном системой представлении
    Ошибки строки, которые нельзя провести без исправления
    Проблемные строки строки, требующие внимания, но не обязательно блокирующие фиксацию факта операции

    Ошибочные строки должны быть визуально связаны с конкретной причиной ошибки. Бухгалтер исправляет ошибки до проведения соответствующих операций.

    Кнопка «Сохранить» является явным действием проведения пачки после проверки.

    Нормативная основа: FIN-REQ-007; FIN-CASE-004.

    Сохранение¶

    После сохранения:

    1. фиксируется пачка ввода;
    2. каждая строка становится отдельной финансовой операцией;
    3. документы и связи сохраняются у соответствующей операции;
    4. финансовое состояние участников и фактический баланс клуба пересчитываются в соответствии с типами проведённых операций.

    Интерфейс после успешного сохранения должен явно показывать результат операции и не оставлять у бухгалтера впечатления, что строки всё ещё являются несохранённым черновиком.

    Ошибки и проблемные состояния¶

    Состояние Поведение интерфейса Нормативная основа
    Перевод без подтверждающего документа строка ошибочная, проведение блокируется до добавления документа FIN-REQ-006, FIN-REQ-007; FIN-CASE-004 A3
    Наличный платёж без документа допустимо FIN-REQ-006, FIN-REQ-007; FIN-CASE-004 A4
    Компенсация сверх незакрытого остатка нормы строка ошибочная, проведение блокируется FIN-REQ-008; FIN-CASE-004 A2
    Расход без требуемого решения-основания факт расхода сохраняется с явной отметкой проблемы FIN-REQ-028; FIN-CASE-004 A5
    Основание не соответствует цели/категории расхода факт расхода сохраняется, несоответствие фиксируется отдельно FIN-REQ-028; FIN-CASE-004 A6

    Навигация и связи¶

    После сохранения пользователь должен иметь возможность перейти от пачки к созданным финансовым операциям и от операции к связанному документу и решению-основанию, если такая связь существует.

    Конкретная компоновка таблицы, порядок колонок, способ выбора участника, категория визуального компонента загрузки файла и иные детали оформления остаются реализационными решениями, если они не противоречат нормативной основе.
