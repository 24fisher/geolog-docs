    Панель дежурного¶

    Назначение¶

    Панель дежурного является единым рабочим интерфейсом для временного дежурства участника клуба. Она не создаёт отдельную постоянную роль «Дежурный»: доступ к рабочим действиям появляется после самостоятельного принятия временных полномочий по GUEST-REQ-011 и прекращается после завершения собственного дежурства.

    Нормативная основа: UI-REQ-014, UI-REQ-017, UI-REQ-018, UI-REQ-021, DUTY-REQ-001–DUTY-REQ-011, GUEST-REQ-007–GUEST-REQ-014, PASS-REQ-018–PASS-REQ-019.

    До начала дежурства¶

    Участнику, который имеет право самостоятельно заступить на дежурство, доступно действие «Заступить на дежурство».

    После его выполнения система фиксирует начало фактического интервала участия и открывает рабочую панель дежурного.

    Состояние активного дежурства¶

    Во время активного дежурства панель явно показывает:

    • что текущий пользователь сейчас дежурит;
    • время начала его текущего интервала;
    • других участников, которые сейчас также находятся на дежурстве;
    • действие «Завершить дежурство».

    Одновременно могут дежурить несколько участников. Завершение собственного дежурства одним участником не прекращает дежурство остальных.

    Основные рабочие действия¶

    Из панели без перехода через несвязанные разделы доступны:

    Проверка пропусков¶

    Дежурный может открыть интерфейс выборочной проверки электронного пропуска и актуального состояния допуска. Проверка не является обязательной для каждого катающегося или каждого подъёма. Особое внимание выборочным проверкам уделяется в январе.

    Если дежурный видит члена клуба, который катается без действующего пропуска, и знает его ФИО, интерфейс позволяет выбрать этого участника и зафиксировать факт катания без действующего пропуска. Запись сохраняет участника, дату и время и пользователя, внёсшего отметку.

    Такая отметка не является автоматическим наказанием. Она передаётся в панель правления как проблема, требующая внимания.

    Гости¶

    Дежурному доступен список ожидаемых гостей на выбранную дату. Для каждого гостя показываются ФИО, пригласивший участник, потребность в гостевом бугеле и состояние инструктажа по технике безопасности: «Не проведён» или «Проведён».

    Панель показывает доступное количество гостевых бугелей, общее количество запрошенных и случаи возможного дефицита с учётом очередности приглашений.

    Инструктаж гостей¶

    Каждый гость до начала катания должен пройти инструктаж по технике безопасности независимо от того, требуется ли ему гостевой бугель. Из списка гостей дежурный может зарегистрировать проведение инструктажа для любого гостя.

    Пока инструктаж не зарегистрирован, интерфейс явно показывает, что гость не считается прошедшим обязательный инструктаж и не должен начинать катание. Если гостю требуется гостевой бугель, система дополнительно не позволяет зарегистрировать его выдачу до регистрации инструктажа.

    После регистрации состояние гостя меняется на «Проведён». Из панели доступен журнал инструктажей гостей в объёме, необходимом для выполнения GUEST-REQ-013–GUEST-REQ-014.

    Если электронный интерфейс был недоступен и инструктаж временно зафиксировали на бумаге, дежурный может позднее внести его в систему по GUEST-REQ-012. При таком вводе интерфейс различает фактическое время инструктажа и время внесения записи и отмечает запись как внесённую постфактум после резервной бумажной фиксации.

    Выдача и возврат гостевых бугелей¶

    Дежурный фиксирует фактическую выдачу и возврат гостевых бугелей. Каждая операция сохраняет связь с гостем и приглашением, количество, фактическое время и пользователя, который зарегистрировал действие.

    Если электронный интерфейс был недоступен, из панели доступен предусмотренный последующий ввод бумажной операции по GUEST-REQ-012. При таком вводе различаются время фактического события и время внесения записи в систему.

    Безопасность подъёмника¶

    Дежурный в реальной работе контролирует безопасную эксплуатацию подъёмника, включает и отключает его, выполняет экстренную остановку, помогает при запутывании бугелей и делает замечания при опасном поведении катающихся.

    Панель является интерфейсом учёта и контроля и не изображает программное управление физическим подъёмником, если фактическое включение, отключение и экстренная остановка выполняются непосредственно на оборудовании.

    История собственных дежурств¶

    После завершения дежурства участнику остаётся доступна собственная история дежурств.

    По умолчанию показываются:

    • текущий сезон;
    • количество зафиксированных дежурств за сезон;
    • перечень дежурств;
    • дата каждого дежурства;
    • фактические интервалы участия.

    Можно выбрать прошлые сезоны.

    Заявка на компенсацию¶

    Из истории дежурств участник может перейти к заявке на компенсацию. Система автоматически подтягивает количество дежурств за выбранный период, по умолчанию за текущий сезон.

    Участник видит исходный перечень дежурств, из которого рассчитано количество. При рассмотрении заявки правление видит то же количество и может по прямой ссылке открыть историю дежурств заявителя, по умолчанию за текущий сезон, с возможностью выбрать прошлые сезоны.

    Система не назначает компенсацию автоматически. Решение принимает правление в установленном организационном порядке.

    Граница интерфейса¶

    Панель не дублирует все данные личного кабинета участника. Её назначение состоит в быстрых действиях, необходимых непосредственно во время дежурства, и в доступе к собственной истории дежурств.
