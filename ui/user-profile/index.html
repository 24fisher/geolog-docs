    Профиль пользователя¶

    Назначение¶

    Профиль пользователя является отдельным экраном для персональных и учётных данных текущего пользователя. Он не является разделом «Мой клуб», не входит в четыре постоянных раздела основной навигации и не подменяет персональную оперативную сводку.

    Точка входа в профиль находится в верхней панели авторизованного интерфейса: пользователь открывает профиль нажатием на собственную иконку.

    Нормативная основа: UI-REQ-024, REG-REQ-004, REG-REQ-006, REG-REQ-015, REG-REQ-017, REG-REQ-019, CHILD-REQ-008, WORK-REQ-023.

    Состав профиля¶

    Личность и клубное положение¶

    Показываются ФИО текущего участника, его понятное клубное положение и все применимые специальные роли. Базовая роль «Участник» отдельно не выводится.

    Пользователь не может из профиля самостоятельно менять клубное положение или специальные роли.

    Фотография профиля¶

    Для взрослого участника используется одна фотография профиля Geolog. Профиль показывает текущую фотографию либо нейтральный стандартный аватар при её отсутствии. Пользователь может выбрать файл с preview, загрузить новую фотографию, заменить существующую или удалить её. После успешного сохранения или удаления изображение в верхней панели обновляется без перезагрузки приложения.

    При подтверждённой привязке Telegram доступно действие «Загрузить фото из Telegram». При первой успешной привязке Telegram система также пытается импортировать доступное фото автоматически, только если фотографии Geolog ещё нет. Отсутствие Telegram-фото не считается ошибкой. Импорт никогда автоматически не перезаписывает существующую фотографию Geolog и сохраняет собственную копию изображения без постоянной синхронизации.

    Контактные данные¶

    Показываются текущий телефон и электронная почта. Пользователь может изменить собственные телефон и email по REG-REQ-017.

    Для email показывается текущее состояние подтверждения. После изменения адрес становится неподтверждённым до прохождения подтверждения по REG-REQ-004.

    История прежних телефонов и email в обычном пользовательском профиле не отображается.

    Закреплённый бригадир¶

    Отдельным блоком показывается закреплённый бригадир по WORK-REQ-023: ФИО и доступные контактные данные для связи по клубным работам.

    Если бригадир не назначен, интерфейс явно показывает «не назначен» и не выводит пустые контактные поля.

    Из профиля пользователь не назначает и не меняет себе бригадира.

    Дети и семейные связи¶

    Связанные с участником дети и доступные действия с ними находятся в профиле. Пользователь видит разрешённые ему сведения и может инициировать добавление ребёнка по CHILD-REQ-008.

    Эти данные не дублируются отдельным постоянным блоком на странице «Мой клуб».

    Внешние каналы и мессенджеры¶

    Профиль показывает подключённые персональные внешние каналы по общей модели REG-REQ-019. Для каждого поддерживаемого провайдера пользователь видит состояние привязки или доступности и применимые действия управления.

    В MVP поддерживаются Telegram, email и Web Push.

    Для Telegram: если привязки нет, пользователь может инициировать её по REG-REQ-006; если связь уже подтверждена, это состояние показывается явно.

    Для email используется текущий основной адрес из контактных данных. Если адрес подтверждён, в блоке внешних каналов показывается переключатель «Получать уведомления по email». При первом появлении подтверждённого основного email рассылка включена по умолчанию. Пользователь может отключить её и позже включить снова.

    Если текущий основной email отсутствует или ещё не подтверждён, интерфейс показывает, что email-уведомления недоступны до добавления/подтверждения адреса, и не создаёт отдельный фиктивный адрес для уведомлений. При смене email сохранённая настройка рассылки не сбрасывается, но доставка приостанавливается до подтверждения нового адреса.

    Email-канал явно обозначается как канал доставки без статуса прочтения и без возможности подтверждения «Ознакомлен» непосредственно из письма.

    Для Web Push показывается отдельный переключатель «Push-уведомления» и фактическое состояние текущего устройства. При включении интерфейс запрашивает системное разрешение только в результате явного действия пользователя и после успешной подписки показывает канал включённым. Пользователь может отключить push для текущего устройства. Если браузер не поддерживает push или системное разрешение запрещено, интерфейс показывает это состояние вместо неработающего включённого переключателя. Push является дополнительной доставкой уведомлений центра и не имеет собственного read-state.

    Интерфейс не должен строиться вокруг единственного специального поля Telegram: добавление нового мессенджера должно выражаться новым провайдером в общем блоке внешних каналов. Ни один внешний канал не заменяет регистрацию и не является самостоятельным доказательством личности.

    Учётная запись¶

    Из профиля доступны действия, относящиеся непосредственно к собственной учётной записи, включая смену пароля по REG-REQ-015.

    Административные действия над другими участниками сюда не входят.

    Граница с другими интерфейсами¶

    «Мой клуб» показывает оперативную персональную сводку: обязательства, состояние сезона, «Требует действий», быстрый ски-пасс и контекстные переходы.

    Профиль пользователя хранит персональные и учётные данные и действия по их управлению.

    «Клуб → Участники» предназначен для разрешённых административных операций над другими участниками по UI-REQ-025.

    Эти три интерфейса не должны смешиваться в один «личный кабинет».

    Доступ и адаптация¶

    Профиль доступен только авторизованному пользователю и работает на компьютере и телефоне. Видимость элементов не заменяет серверную проверку полномочий.

    Конкретная сетка, цвета, размеры карточек и визуальные детали не являются бизнес-правилами, если иное прямо не установлено нормативными требованиями.
