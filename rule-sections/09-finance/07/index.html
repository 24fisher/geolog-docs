    Самостоятельное сообщение участника об оплате¶

    Этап: MVP

    FIN-REQ-050. Реквизиты для пользовательского перевода¶

    Система хранит актуальные реквизиты, которые показываются участнику при самостоятельном переводе денег клубу: фамилию и инициалы получателя, название банка, номер телефона для перевода, номер счёта и выбранный активный способ перевода.

    Активный способ перевода имеет одно из значений: перевод по номеру телефона либо перевод по номеру счёта. Пользовательская инструкция строится из текущих настроек и не содержит захардкоженных реквизитов в клиенте. Для перевода по номеру телефона показываются получатель, банк и телефон; для перевода по номеру счёта — получатель, банк и номер счёта.

    При переводе по номеру телефона после загрузки реквизитов клиент автоматически копирует номер получателя в буфер обмена и явно сообщает об успешном копировании. На экране остаётся отдельное действие повторного копирования номера. Сумма автоматически не копируется и отдельного действия копирования суммы нет.

    Для ручного перевода интерфейс может запустить приложение «СберБанк Онлайн» только на его стартовый экран, без перехода во внутренний платёжный сценарий и без передачи номера телефона, суммы, назначения или комментария. На Android для этого используется launcher intent установленного пакета ru.sberbankmobile; на iOS — scheme onlineios-app:// без path/query. Если платформа не мобильная, используется web fallback СберБанк Онлайн. После запуска пользователь вручную переходит к переводу по номеру телефона и вставляет уже скопированный номер. Интерфейс явно указывает не заполнять назначение или комментарий к переводу.

    Реквизиты являются эксплуатационными системными настройками по SET-REQ-004 и не являются денежным лимитом или порогом по FIN-REQ-029–FIN-REQ-033.

    Этап: MVP

    FIN-REQ-051. Уведомление о новом денежном начислении¶

    При создании нового автоматического денежного начисления участнику система создаёт одно обычное персональное уведомление в общем центре уведомлений. Правило применяется как минимум к сезонному членскому взносу и к денежной задолженности, возникшей из незакрытой нормы отработок.

    Уведомление содержит понятное человеку название обязательства, сумму, сезон или иное основание начисления и, пока начисление не погашено, действие «Сообщить об оплате».

    Автоматическое уведомление о денежном начислении создаётся во внутреннем центре уведомлений для каждого участника, которому создано начисление.

    Для этого события email не отправляется и не ставится в почтовую очередь. Email-подавление не должно мешать созданию внутреннего уведомления. Telegram и Web Push, если они доступны и разрешены общими настройками пользователя, продолжают использовать общий notification mechanism.

    Повторное восстановление уже существующего начисления не создаёт дубликат уведомления об одном и том же начислении.

    Этап: MVP

    FIN-REQ-052. Сообщение участника о выполненном переводе¶

    Участник может сообщить о выполненном переводе из уведомления о начислении, из экрана собственных взносов и из пользовательского сценария оплаты при отсутствии допуска.

    Перед отправкой система показывает актуальные реквизиты по FIN-REQ-050. Участник прикладывает скриншот или иной файл подтверждения из банка. Система сохраняет сообщение об оплате отдельно от проведённой финансовой операции как минимум с участником, временем отправки, приложенным подтверждением и связанным пользовательским расчётом или обязательством, если оно было выбрано.

    Само сообщение об оплате, загрузка подтверждения или нажатие кнопки не уменьшают задолженность, не создают проведённый приход и не восстанавливают допуск. Фактическое поступление регистрируется бухгалтером по FIN-REQ-006; только после регистрации платежа пересчитываются финансовое состояние и зависящий от него допуск.

    Интерфейс после успешной отправки показывает состояние, из которого понятно, что сообщение принято и ожидает бухгалтерской обработки. Повторная отправка подтверждения не должна сама по себе создавать дубликат проведённого платежа.

    Этап: MVP

    FIN-REQ-053. Расчёт суммы для погашения обязательств¶

    В пользовательском сценарии оплаты система серверно рассчитывает доступные суммы погашения из актуальных обязательств участника.

    Если существует непогашенный сезонный членский взнос, доступен вариант «Клубный взнос». Если одновременно существует непогашенная денежная задолженность за незакрытую сезонную норму отработок, дополнительно доступен вариант «Клубный взнос + недоработка».

    Для недоработки интерфейс показывает объяснимый расчёт: непогашенный объём в днях × применённая к сезону стоимость компенсации одного дня = сумма денежной компенсации. Ниже одним и тем же поясняющим текстом для всех пользователей показываются применённые к сезону нормы для мужчин и женщин и стоимость компенсации одного дня. Индивидуальный итог рассчитывается из фактических обязательств конкретного участника; пол пользователя не используется клиентом для повторного вычисления нормы.

    Выбранный вариант определяет показываемую сумму и инструкцию к переводу, но не изменяет общий порядок распределения фактически зарегистрированного платежа по FIN-REQ-048. Если фактический платёж отличается от рассчитанной подсказки, бухгалтер регистрирует реально поступившую сумму, после чего сервер применяет действующие правила распределения.
