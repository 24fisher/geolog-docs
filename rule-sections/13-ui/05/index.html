    Основная навигация личного кабинета¶

    UI-REQ-020. Основная навигация личного кабинета¶

    Основная личная навигация содержит четыре смысловых раздела: «Мой клуб», «Катание», «Работы» и «Клуб». Разделы группируют пользовательские задачи по цели, а не повторяют структуру бизнес-модулей или хранилища данных. При наличии постоянной основной навигации главная страница «Мой клуб» не дублирует отдельными кнопками переходы в эти же основные разделы.

    • «Мой клуб» является персональной главной страницей. Здесь находятся блок «Требует действий», краткое состояние собственных взносов и отработок, быстрый доступ к электронному ски-пассу и другие применимые персональные сводки.
    • «Катание» объединяет связанные с катанием процессы: управление пропусками, гостевые приглашения, собственные заказы на бугели и собственную историю дежурств. Если пользователю доступна рабочая панель дежурного, вход в неё предоставляется отсюда.
    • «Работы» объединяют ближайшие рабочие дни, планы приезда, личные отработки и связанные с работами действия. Если пользователю доступна бригадирская панель, вход в неё предоставляется отсюда.
    • «Клуб» объединяет общеклубные процессы и информацию: события, инициативы, голосования, обращения, документы, решения и информационные кампании. Общая финансовая информация клуба по UI-REQ-004 также открывается внутри этого раздела, если она доступна пользователю.

    Связанные с детьми данные и действия не образуют постоянный пятый раздел и не выводятся отдельным блоком на «Мой клуб». Они доступны из профиля пользователя по UI-REQ-024.

    Рабочие панели, доступные только отдельным пользователям или временным полномочиям, не включаются в постоянную основную навигацию для всех. Например, бригадирская панель открывается из «Работы», дежурная из «Катание», бухгалтерская из подходящего финансового контекста, если у пользователя есть соответствующие права.

    Для пользователей с соответствующими полномочиями из раздела «Клуб» доступен рабочий интерфейс «Участники» по UI-REQ-025. Он предназначен для административных действий над другими участниками и не смешивается с личным профилем текущего пользователя.

    Для пользователей, которым серверная авторизация предоставляет доступ к просмотру или изменению зарегистрированных бизнес-настроек, из раздела «Клуб» доступен рабочий интерфейс «Настройки» по UI-REQ-026. Он не становится постоянным пунктом навигации для пользователей без соответствующих полномочий.

    Наличие процесса внутри смыслового раздела само по себе не означает обязательного действия. Обязательные действия продолжают выводиться отдельно в блоке «Требует действий».

    Этап: MVP

    UI-REQ-021. Фиксация катания без пропуска и проблема для правления¶

    В рабочей панели дежурного доступно действие фиксации факта катания без действующего пропуска для известного дежурному члена клуба, которого можно однозначно выбрать по ФИО. Интерфейс сохраняет отметку по правилам DUTY-REQ-010 и не должен создавать видимость автоматического наказания участника.

    В панели правления такие отметки показываются отдельными проблемами, требующими внимания. Для каждой проблемы доступны как минимум участник, дата и время фиксации и пользователь, который внёс отметку. Элемент ведёт к исходной записи и не создаёт автоматического решения или санкции.

    Этап: После MVP

    UI-REQ-022. Рабочая панель бухгалтера¶

    Пользователю с бухгалтерскими полномочиями доступна единая рабочая панель бухгалтера. Панель объединяет бухгалтерскую работу и не подменяет общую финансовую панель клуба по UI-REQ-004.

    В панели доступны как минимум разделы «Сводка», «Входящие», «Ввод операций», «Операции», «Документы», «Обязательства участников» и «Расходы клуба».

    Раздел «Входящие» показывает заявки, дошедшие до этапа действия бухгалтера по нормативным финансовым правилам. Для заявки на возмещение личных расходов бухгалтер видит как минимум заявителя, дату покупки, сумму, категорию, описание, подтверждающий документ, основание при его наличии, требуемое подтверждение хозяйственной необходимости и состояние предварительного согласования, когда оно применимо. Интерфейс позволяет выполнить предусмотренные FIN-REQ-015–FIN-REQ-023 действия бухгалтера, не обходя установленный порядок рассмотрения.

    Массовый ввод членских взносов, денежных компенсаций субботников и клубных расходов выполняется внутри этой панели как раздел «Ввод операций». Зарегистрированные операции, связанные документы, обязательства участников и клубные расходы доступны в соответствующих рабочих разделах в пределах бухгалтерских полномочий.

    Из заявки бухгалтер может перейти к связанному подтверждающему документу и участнику, а после возникновения связанной финансовой операции — к этой операции. Из финансовой операции доступны обратные связи с документом, участником и решением-основанием, когда такие связи предусмотрены финансовыми правилами.

    Наличие объекта во «Входящих» означает необходимость бухгалтерского действия только тогда, когда профильный финансовый процесс действительно дошёл до бухгалтерского этапа; интерфейс не создаёт новые основания для согласования, выплаты или отказа.

    Этап: MVP

    UI-REQ-025. Управление участниками¶

    Административные действия над другими участниками не размещаются в личном профиле текущего пользователя. Для управления участниками используется отдельный рабочий интерфейс «Участники» с точкой входа из раздела «Клуб» для пользователей, которым доступны соответствующие полномочия.

    В интерфейсе «Участники» объединяются действия над записями участников, относящиеся к управлению составом и доступом, в том числе создание записи взрослого участника, выпуск и перевыпуск персональной регистрационной ссылки по REG-REQ-003, а также назначение, изменение и прекращение закрепления бригадира по WORK-REQ-024.

    Интерфейс группирует эти операции вокруг реестра и карточки конкретного участника. Наличие раздела или видимость действия не предоставляет полномочий: доступ к каждой операции определяется серверной авторизацией и профильными требованиями. В частности, возможность выпуска регистрационной ссылки предоставляется только пользователю, которому это разрешено REG-REQ-003, и не превращает системного администратора в члена правления или наоборот.

    «Участники» не является личным кабинетом и не содержит действия, относящиеся только к собственному профилю текущего пользователя. Самостоятельное изменение своих контактных данных, управление собственными семейными связями, привязка Telegram и смена пароля остаются в профиле по UI-REQ-024.

    Рабочие операции других ролей не переносятся в «Участники»: бухгалтерская работа выполняется в панели бухгалтера по UI-REQ-022, организация и подтверждение работ — в рабочих интерфейсах раздела «Работы», а технические действия системного администратора остаются отдельными от бизнес-управления клубом в соответствии с ACCESS-REQ-003.

    Этап: MVP

    UI-REQ-024. Профиль пользователя¶

    В верхней панели авторизованного интерфейса иконка текущего пользователя является точкой входа в его личный профиль. Нажатие на неё открывает отдельный экран профиля. Профиль не является пятым разделом основной навигации и не подменяет главную страницу «Мой клуб»: «Мой клуб» остаётся оперативной персональной сводкой, а профиль содержит персональные и учётные данные и действия по их управлению.

    В профиле отображаются как минимум ФИО участника, текущий контактный телефон, текущая электронная почта, клубное положение и применимые специальные роли. Телефон и электронную почту пользователь может самостоятельно изменить по REG-REQ-017. Для электронной почты интерфейс показывает актуальное состояние подтверждения и после изменения нового адреса позволяет пройти его подтверждение по REG-REQ-004. История прежних телефонов и адресов электронной почты в обычном пользовательском профиле не отображается.

    Отдельным блоком показывается закреплённый бригадир участника по WORK-REQ-023: ФИО и доступные контактные данные бригадира, необходимые для организационной связи по клубным работам. Если закреплённый бригадир отсутствует, интерфейс явно сообщает «не назначен» и не показывает пустые контактные поля.

    Связанные с участником дети и действия с ними размещаются в профиле. Пользователь видит доступные ему сведения о связанных детях и может инициировать добавление ребёнка по CHILD-REQ-008. Дети не дублируются отдельным постоянным блоком на главной странице «Мой клуб».

    В профиле отдельным блоком показываются персональные внешние каналы и мессенджеры по общей модели REG-REQ-019. Для каждого поддерживаемого провайдера интерфейс показывает состояние привязки или доступности и применимые действия управления. В MVP поддерживаются Telegram и email. Для Telegram сохраняется сценарий привязки по REG-REQ-006. Для email используется текущий основной подтверждённый адрес пользователя; при его наличии профиль показывает переключатель получения уведомлений по email по NOTIF-REQ-016. Рассылка включена по умолчанию после появления подтверждённого основного email и может быть отключена/включена пользователем. При отсутствии или неподтверждённости текущего email интерфейс показывает недоступность email-канала до подтверждения адреса. UI не должен моделировать Telegram как единственное специальное поле учётной записи: новые мессенджеры добавляются как новые провайдеры общего блока внешних каналов.

    В профиле также размещаются относящиеся непосредственно к учётной записи действия, включая смену пароля по REG-REQ-015. Профиль не предоставляет пользователю возможность самостоятельно менять клубное положение, специальные роли, закреплённого бригадира или иные данные, изменение которых нормативно отнесено к полномочиям других пользователей.

    Этап: MVP
