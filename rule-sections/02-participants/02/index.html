    Первоначальный перенос участников¶

    Этап: MVP

    MEM-REQ-004. Массовый первоначальный импорт¶

    Для первоначального заполнения Geolog существующим составом клуба должен поддерживаться массовый импорт участников из табличного файла Excel или CSV. Импорт является механизмом переходной миграции исходных данных, а не постоянным способом ведения реестра участников.

    До официального завершения перехода на Geolog исходный реестр может продолжать изменяться. Поэтому первоначальный импорт допускается выполнять повторно: повторная загрузка актуализированного исходного реестра должна сопоставлять уже перенесённых участников с существующими записями Geolog и не создавать их повторно. Новые, изменившиеся и неоднозначно сопоставленные строки должны быть показаны пользователю до подтверждения.

    Автоматическое сопоставление не должно основываться только на совпадении ФИО. Неоднозначное сопоставление требует явного решения уполномоченного пользователя.

    Импорт создаёт и обновляет записи участников независимо от наличия учётных записей. Регистрация и выдача доступа выполняются после переноса данных отдельным процессом.

    Перенос финансовых операций и отработок текущего сезона не является побочным эффектом повторного импорта состава участников и выполняется отдельным процессом миграции. После установленного момента завершения перехода актуальным источником данных становится Geolog, а первоначальный табличный реестр сохраняется только как архивный источник миграции.

    Этап: MVP

    MEM-REQ-005. Права на первоначальный импорт¶

    Первоначальный массовый импорт может выполнять действующий член правления либо системный администратор. Для системного администратора это явно разрешённое действие первоначальной миграции, а не общее право самостоятельно принимать бизнес-решения о составе клуба.

    Факт импорта журналируется: сохраняются как минимум исполнитель, дата и время, сведения об исходном файле, количество обработанных, успешно принятых и отклонённых строк, а также созданные или сопоставленные записи участников.

    Этап: MVP

    MEM-REQ-006. Состав данных первоначального импорта¶

    Первоначальная миграция переносит из утверждённого исходного клубного реестра данные, необходимые Geolog для дальнейшей работы. Исходный реестр не переносится как полный исторический архив: исторические сведения переносятся структурированно только тогда, когда они продолжают иметь бизнес-последствия после перехода на Geolog.

    Для действующих участников переносятся доступные актуальные данные, необходимые для продолжения работы системы: идентификационные сведения, все распознанные телефонные номера, электронная почта, текущее положение в клубе, однозначно определяемые роли и льготы, поручители, профиль работ, закреплённый бригадир, рабочая зона участника и данные текущего сезона, которые должны продолжать учитываться после перехода.

    Исходный «год вступления» означает год начала первого известного кандидатского периода. Отдельное поле «год вступления» не создаётся: значение сохраняется в истории кандидатского статуса с фактической известной точностью до года, без подстановки фиктивных дня и месяца.

    Для исходной колонки Год рожд / Год вступ действует правило разбора: если распознаны два года, первый трактуется как год рождения, второй — как год начала первого известного кандидатского периода. Если в ячейке указан только один год, он трактуется как год вступления, а год рождения считается неизвестным. Единственный год нельзя автоматически использовать как год рождения.

    Неизвестный год рождения взрослого участника сам по себе не делает строку ошибочной и не блокирует создание записи при импорте. В таком случае запись создаётся с явно неизвестными данными рождения и пометкой о необходимости последующего уточнения.

    Для действующих участников колонка исходного реестра «Бригада» используется для первоначального определения закреплённого бригадира, а колонка «Подъемник» — для первоначального определения рабочей зоны участника. Поручители связываются с существующими участниками только при однозначном сопоставлении; неоднозначность требует проверки и не создаёт связь автоматически. Профиль работ сохраняется как свободный текст без автоматической классификации.

    Для ранее состоявших в клубе обязательно сохраняются сама запись участника, доступные основные идентификационные сведения, все распознанные телефонные номера, электронная почта, известный год начала первого кандидатского периода, текущее неактивное положение, непогашенная задолженность и необходимые для понимания записи примечания. Это позволяет при возвращении использовать существующую запись участника и сохранить обязанность погасить прежний долг.

    Старые отработки, взносы, пропуска, закреплённый бригадир, рабочая зона, поручители, профиль работ, служебные признаки и иные сезонные сведения бывшего участника, которые больше не создают бизнес-последствий, не требуется переносить в Geolog структурированно. Они остаются доступными в архивном исходном реестре.

    Обозначение П исходного реестра переносится как роль «Член правления», если оно однозначно относится к действующему участнику. Обозначение ПРЕДС означает председателя клуба. Поскольку отдельной должности или роли председателя в действующей модели Geolog нет, при первоначальной миграции это значение сохраняется в примечании участника и не создаёт новую роль или полномочие.

    Если значение необходимо для дальнейшей работы Geolog, но его нельзя надёжно преобразовать в структурированные данные, оно не должно молча отбрасываться или получать придуманный бизнес-смысл. Такое значение показывается при предварительной проверке и сохраняется в предусмотренной для миграции форме после явного подтверждения.

    Конкретное расположение и названия колонок исходного файла не являются частью бизнес-модели Geolog. Механизм миграции адаптируется к утверждённому исходному реестру.

    Этап: MVP

    MEM-REQ-007. Проверка перед подтверждением импорта¶

    Импорт выполняется через предварительную проверку. До создания записей пользователь должен увидеть результат разбора файла, ошибки обязательных данных, возможные совпадения с уже существующими участниками и итоговое количество записей, которые будут созданы или сопоставлены.

    Ошибочные строки не должны незаметно превращаться в участников. Возможные совпадения не должны автоматически объединяться только по ФИО. Пользователь должен иметь возможность исправить исходный файл либо разрешить предусмотренные интерфейсом проблемы до окончательного подтверждения импорта.

    Этап: MVP

    MEM-REQ-008. Настройка после импорта¶

    После первоначального импорта импортированные роли, закреплённые бригадиры, рабочие зоны, поручители и другие однозначно определённые данные сохраняются как начальное состояние Geolog. Отсутствующие, неоднозначные или последующие изменения выполняются средствами самой системы. Для массовых первоначальных настроек интерфейс должен поддерживать групповые операции там, где последовательное открытие карточки каждого участника создаёт неоправданную ручную работу.

    После подготовки записей участников уполномоченный пользователь может выпускать регистрационные ссылки и запускать процесс активации учётных записей по правилам регистрации. Наличие импортированной записи участника само по себе не предоставляет доступ к закрытой системе.
